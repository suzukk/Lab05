# Лабораторийн ажил №5 — API Testing

## Оюутны мэдээлэл

- **Оюутны нэр:** С.Тэргэл
- **Оюутны код:** B232270011
- **Үйлдлийн систем:** Arch Linux
- **Node.js:** v26.8.1
- **Newman:** 6.2.2

## 1. Лабораторийн ажлын зорилго

Энэхүү лабораторийн ажлын зорилго нь REST API-ийн ажиллагааг Postman Collection болон Newman ашиглан автоматжуулсан байдлаар шалгах юм. Туршилтаар оюутны хичээлд бүртгүүлэх үйлдлийн амжилттай, алдаатай болон хязгаарын нөхцөлүүдийг шалгасан.

## 2. Ашигласан технологи

- Node.js — API сервер ажиллуулах
- Postman Collection — API хүсэлт болон тестийн нөхцөлүүдийг тодорхойлох
- Newman — Collection-ийг командын мөрөөс ажиллуулах
- Git, GitHub — Хувилбарын удирдлага

## 4. Equivalence Partitioning

Оролтын өгөгдлийг ижил үр дүн хүлээгдэж буй бүлгүүдэд ангилсан.

| Оролтын бүлэг | Жишээ | Хүлээгдэх үр дүн |
|---|---|---|
| Идэвхтэй, хүчинтэй оюутан | `B231234567` | Бүртгэл амжилттай |
| Байхгүй оюутан | Бүртгэлгүй ID | `ERROR_NO_STUDENT` |
| Идэвхгүй оюутан | `B231111111` | `ERROR_INACTIVE_STUDENT` |
| Хичээл олдохгүй | Бүртгэлгүй course ID | `ERROR_NO_COURSE` |
| Урьдчилсан нөхцөлийг огт судлаагүй | Шаардлагатай хичээлүүдийн аль нь ч судлагдаагүй | `ERROR_PREREQUISITES` |
| Урьдчилсан нөхцөлийн заримыг судалсан | Шаардлагатай хичээлүүдээс зарим нь судлагдсан, зарим нь судлагдаагүй | `ERROR_PREREQUISITES` |
| Урьдчилсан нөхцөл бүрэн хангагдсан | Шаардлагатай бүх хичээл судлагдсан | Бүртгэл амжилттай |
| Шаардлагатай талбар дутуу | `studentID` эсвэл `courseID` байхгүй | HTTP 400 |

## 5. Давхар алдааны спецификаци (Double-Fault Specification)

Нэг хүсэлтэд хоёр ба түүнээс олон алдаатай нөхцөл зэрэг үүсэхэд API аль алдааг түрүүлж буцаахыг шалгах спецификаци.

| № | Давхар алдааны нөхцөл | Хүлээгдэх үр дүн | Тайлбар |
|---|---|---|---|
| 1 | `studentID` байхгүй, `courseID` буруу | HTTP 400 (`ERROR_BAD_REQUEST`) | Шаардлагатай талбарын шалгалт түрүүлнэ |
| 2 | Оюутан бүртгэлгүй, хичээл байхгүй | `ERROR_NO_STUDENT` | Оюутны шалгалт хичээлийн шалгалтаас түрүүлнэ |
| 3 | Оюутан идэвхгүй, хичээл байхгүй | `ERROR_INACTIVE_STUDENT` | Идэвхтэй эсэхийг шалгах нь хичээл хайхаас түрүүлнэ |

Эдгээр тохиолдол нь API-ийн validation дарааллын дагуу хүлээгдэх алдааны үр дүнг тодорхойлно.

## 6. Boundary Value Analysis

Хичээлд бүртгүүлэх үеийн урьдчилсан нөхцөлийн шалгалтад дараах хил заагийн нөхцөлийг авч үзсэн.

| Нөхцөл | Тестийн утга | Хүлээгдэх үр дүн |
|---|---|---|
| Урьдчилсан нөхцөл байхгүй | `CS400` | Бүртгэл амжилттай |
| Урьдчилсан нөхцөл шаардлагатай боловч хангаагүй | `CS313`, `CS201` судлаагүй | `ERROR_PREREQUISITES` |
| Урьдчилсан нөхцөл хангагдсан | `CS201` судалсан | Бүртгэл амжилттай |

## 7. Туршилтын үр дүн

### PASS — Амжилттай туршилт

Файл: `results/newman-pass.txt`

- Requests: 28
- Assertions: 28
- Failed assertions: 0
- Exit code: 0

Бүх assertion амжилттай биелсэн.

### FAIL — Алдаатай assertion

Файл: `results/newman-fail.txt`

Энэ туршилтад амжилттай бүртгүүлэх хүсэлтийн хүлээгдэж буй HTTP статусыг зориудаар `201` биш `200` болгон өөрчилсөн.

- Requests: 28
- Assertions: 28
- Failed assertions: 1
- Exit code: 1

API бодитоор HTTP 201 буцаасан тул зориудаар өөрчилсөн assertion унасан.

### DOWN — Сервер ажиллахгүй үеийн туршилт

Файл: `results/newman-down.txt`

API серверийг зогсоосны дараа Collection-ийг ажиллуулсан.

- Requests: 28
- Холболтын алдаа: 28
- Failed assertions: 28
- Exit code: 1
- Алдаа: `ECONNREFUSED 127.0.0.1:3000`

Сервер ажиллахгүй үед 28 хүсэлт бүгд `ECONNREFUSED` холболтын алдаа авсан. JSON response ирээгүй тул зарим assertion JSON parse алдаа мөн харуулсан.

### Interface error ба Oracle error-ийн ялгаа

- **Interface error:** API сервертэй холбогдох үед гардаг алдаа. Жишээ нь сервер унтарсан үед `ECONNREFUSED` гарна.
- **Oracle error:** Тестийн хүлээгдэж буй үр дүн (expected result) бодит үр дүнтэй (actual result) таарахгүй үед assertion унадаг. Жишээ нь HTTP 201 хүлээгдэж байхад HTTP 200 гэж буруу заасан бол assertion алдаа гарна.

Иймээс DOWN туршилтын `ECONNREFUSED` нь интерфейс/холболтын алдаа, FAIL туршилтын буруу статусын assertion нь oracle буюу хүлээгдэж буй үр дүнгийн алдаа юм.

## 8. Туршилт ажиллуулах

API серверийг нэг терминалд асаана:

```bash
node server.js
```

Өөр терминалд PASS туршилтыг ажиллуулна:

```bash
newman run lab05-collection.json \
  --env-var "baseUrl=http://localhost:3000" \
  -r cli
```

FAIL туршилт:

```bash
newman run lab05-collection-fail.json \
  --env-var "baseUrl=http://localhost:3000" \
  -r cli
```

DOWN туршилтыг хийхийн өмнө API серверийг зогсооно.

## 9. Дүгнэлт

Энэ лабораторийн ажлаар REST API-г Newman ашиглан автоматжуулсан байдлаар туршиж сурлаа. Амжилттай бүртгүүлэх болон алдаатай оролтын нөхцөлүүдийг шалгасан. Equivalence Partitioning аргаар оролтын өгөгдлийг хүчинтэй болон хүчин төгөлдөр бус бүлгүүдэд ангилсан. Boundary Value Analysis аргаар урьдчилсан нөхцөлтэй болон нөхцөлгүй хичээлийн бүртгэлийг шалгасан. PASS туршилтаар 28 assertion бүгд амжилттай биелсэн. FAIL туршилтад нэг assertion-ийг зориудаар буруу болгож, тестийн систем алдааг илрүүлж байгааг баталсан. DOWN туршилтаар сервер ажиллахгүй үед холболтын алдаа гарч байгааг шалгасан. Newman-ийн гаралтын үр дүнг тус тусад нь файлд хадгалсан. Энэхүү ажлаар API тестийн кейс боловсруулах, автоматжуулах болон үр дүнг тайлбарлах дадлага эзэмшлээ.
